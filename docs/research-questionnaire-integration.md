## 当前操作与代码

- 完整研究 phase 3 挂载实际 `ResearchQuestionnaireEditor.vue`，接收同一任务的问卷草稿和未正式确认的方案变量。已有问卷快捷入口 phase 0 使用独立任务，传入 `plan:null`。
- 可编辑卷首、单选/多选/量表/数值/开放文本题、选项编码、变量对应、未知项、试填轮次/发现/修订；保存使用已有本机目录和失败保稿机制。没有生成受访者、答卷或试填数据。
- `src/types/research-contracts.ts` 添加任务问卷字段和事件；`src/utils/researchQuestionnaire.ts` 适配真实契约、检查重复ID/非有限数/字段类型/失效题目引用；`researchDrafts.ts` 负责旧任务补空稿、有效字段恢复和任务/阶段/修订校验；`src/stores/research.ts` 接事件并保留未保存编辑。
- `src/views/research/ResearchQuestionnaireHost.vue` 做深层只读、事件检查、本机保存和正式请求未接入反馈。`ResearchWorkspaceView.vue` 挂完整研究与独立入口，首页显示前四阶段本机可编辑。
- 问卷 `questions[].measureId` 是变量关系真值，反向题号由消费者按此推导。**不回写上游 `plan.measures[].questionIds`**，避免编辑问卷使上游方案指纹和历史草稿被改写。这是对交接建议的明确接入取舍；正式固定版本映射仍需 BA 对齐。
- 已删除或改变采集方式的变量、已删除的题目关联会明确显示并可重新选择；删除题目时保留反馈正文，将相应发现关联退回“全卷”。

## 真实性与已修问题

F 原件的“固定为正式问卷”改为“本机标记当前问卷”。`signature` 只检查内容变更，未生成服务器 `versionId`。手工录入通过仅显示“录入资料符合本机检查”，不代表核验真实发生的预测试。

接入时发现并修复：

1. 原预测试判断可能接受零人、无效日期、缺渠道、空发现或缺修订说明。现在这些情况不能通过本机检查；不自动补写证据。
2. 原本机标记只比较问卷指纹，删除所引试填轮次后仍有效并出现“第0轮”。现在同时核对依据轮次存在、指纹一致及录入资料检查状态；失效后显示明确原因，并可按当前有效轮次重新标记。
3. 原检查结果仍宣称“已固定正式版本”。已统一为本机标记及其失效，正式保存、阶段确认与发布保持待接入。

正式候选按钮只发出上下文事件，Host 明确提示未接入。没有真实 AI 请求、正式阶段推进或发布成功，也没有回写前面三阶段。
