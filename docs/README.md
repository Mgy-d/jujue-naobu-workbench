## 已确定的共同方向

- 品牌继续为“拒绝脑补”，全站保留雾蓝，借用数模演易版式。
- 市调七阶段、问卷、样例核对、报告编辑、成果版本、来源和备份是保留的业务核心。
- 工程分层参考 scdc 的 Vue 项目，前端统一框架；不把原React应用与旧数学建模应用一起塞进页面。
- 本次只交付文档。后端路线开放，真实AI/解析/统计/认证/云同步不因前端迁移自动具备。
- 用户先前偏向B，随后明确要求A/B各准备方案与计划；这四份文档用于比较，不自行选案开工。

## 两案真正不同的地方

| 比较项 | A | B |
| --- | --- | --- |
| 外层站点页面 | 数模演易式首页、列表、详情、项目与成果 | 相同 |
| 项目工作台 | 顶部七阶段、项目切换、对话、右侧待确认/成果/过程 | 左侧项目与七阶段、中间对话、右侧成果 |
| 确认动作 | 需要建立绑定当前版本的待确认面板 | 保留现有当前任务/保存/确认的行为 |
| 长问卷和报告 | 要重新解决右侧页签、确认和长编辑如何协作 | 沿用已有逐题、目录、正文前置与专注模式，再Vue化 |
| 可复用部分 | 站点版式、业务规则、材料、部分接口机制 | 相同；另有较明确的工作台行为对照 |
| 主要新增风险 | 阶段导航与确认错位、右栏切换丢稿、长编辑挤压 | React转Vue语义变化、站点顶栏与三栏高度冲突 |
| 适合的优先目标 | 更强调全站布局统一，愿意重验工作台交互 | 更强调保护已形成的市调编辑体验，先降低行为变化 |

**建议仍优先考虑 B。** 依据是工作台行为变化较少，不是已测工期、真实用户偏好或“B不需要重写”的承诺。A应通过相同29题和长报告任务证明其右侧确认/编辑组织有价值。

## 开发与验收怎么推进

每案分10项任务：工程与版本验证 → 类型/业务规则 → 存储/旧备份 → 站点页面 → 对应工作台 → 问卷 → 样例分析 → 报告与导出 → 任务工具 → 整体交付。
前四项和多数业务组件可按同一契约准备；选案后只建设所选布局，不同时维护两套产品。
共同验收28项，每案另有4项布局专项，均为**计划中的验收场景**，不是已经通过的测试。

先交付能从新首页进入、编辑并保存的工作台小样，再用实际改动和缺陷重估后续投入；本次不报固定完成日期。
最终交付入口、真实服务协议和最终依赖版本在对应验证节点明确，不用历史README配置代替当前核验。

## 实施前需要评审的内容

1. 选A或B，以及是否接受所列页面与业务范围。
2. 核对共同模型、保存/采用/历史/恢复规则，避免后续两种实现产生不同含义。
3. 审阅首批任务与验收；之后再决定执行方式。
